# ぺぇのつくったもの

ぺぇがつくったアプリと、各種リンクを紹介するサイトです。
HTML・CSS・JavaScriptだけで動く静的サイトで、GitHub Pagesでそのまま公開できます（ビルド不要）。

- 公開ページ：`index.html`
- 更新ツール：`editor/index.html`（フォームで作品やリンクを編集し、公開用ファイルを書き出す）

## フォルダ構成

```
index.html          公開ページ
styles.css          公開ページの見た目
app.js              表示処理・データの検証（更新ツールと共有）
data/site.json      サイト名・紹介文・作品・リンクのデータ（これ1つだけ）
assets/             プロフィール画像・作品画像・ファビコン
  profile.png         青うさぎのアイコン（元画像のまま）
  favicon-32.png      ファビコン
  apple-touch-icon.png  ホーム画面用アイコン
editor/             更新ツール
  index.html / editor.css / editor.js
  zip.js            ZIP書き出し（外部ライブラリなしの自前実装）
.nojekyll           GitHub Pagesで余計な変換をさせないための空ファイル
```

## 1. はじめての公開

### 1-1. リポジトリを作る

リポジトリ名によって、公開URLが変わります。どちらでも動きます。

| リポジトリ名 | 公開URL |
|---|---|
| `<アカウント名>.github.io` | `https://<アカウント名>.github.io/` |
| それ以外（例：`portfolio`） | `https://<アカウント名>.github.io/portfolio/` |

GitHub Desktopを使う場合の手順です。

1. GitHub Desktopで **File → Add local repository…** を選び、このフォルダ（`portfolio`）を指定する。
2. 「このフォルダはGitリポジトリではありません」と表示されたら **create a repository** を押し、そのまま **Create repository** を押す。
3. **Publish repository** を押す。
   - Name：上の表を見てリポジトリ名を決める
   - **Keep this code private のチェックを外す**（無料プランのGitHub Pagesは公開リポジトリが対象です）
4. Publishすると、GitHub上にリポジトリができ、ファイルがアップロードされる。

> すでにGitHub上にリポジトリを作ってある場合は、そのリポジトリをCloneして、このフォルダの中身（`.claude` フォルダ以外）をClone先にコピーし、コミット・Pushしてください。

### 1-2. GitHub Pagesを有効にする

1. GitHubでリポジトリのページを開き、**Settings → Pages** を開く。
2. **Build and deployment** の **Source** で **Deploy from a branch** を選ぶ。
3. **Branch** で `main`、フォルダは `/ (root)` を選び、**Save** を押す。
4. 数分待つと、同じ画面の上部に「Your site is live at …」と公開URLが表示される。

### 1-3. 表示を確認する

- 公開URLを開き、青うさぎのアイコン・サイト名・作品9件（Webアプリ7件、Androidアプリ2件）が表示されることを確認します。
- 表示が古いときは、数分待ってから再読み込み（スマホは強制的に再読み込み）してください。

## 2. 更新のしかた

### 2-1. 更新ツールを開く

更新ツールは、公開URLの末尾に `editor/` を付けた場所にあります。

- 例：`https://<アカウント名>.github.io/editor/`
- 例：`https://<アカウント名>.github.io/portfolio/editor/`

公開ページには更新ツールへのリンクはありません。ブックマークしておいてください。

> **注意**：URLを知っている人は誰でも更新ツールを開けます。ただし、他の人が操作しても、その人の端末の中で下書きが作られるだけです。公開サイトやリポジトリは変更できません。URLを知られないようにすることは、パスワードのような保護にはなりません。

### 2-2. 編集する

- **サイトの基本情報**：サイト名・表示名・紹介文・プロフィール画像
- **作品**：作品名・種別（Web／Android）・URL・説明・ボタンの文言・画像（アイコンかスクリーンショット）・公開するかどうか
- **各種リンク**：表示名・URL・アイコン・公開するかどうか

並べ替えは、各項目の ↑ ↓ ボタンで行います。並び順がそのまま公開ページの表示順になります。

> **「非表示」は秘密にする機能ではありません。** 非表示にした項目も公開用の `site.json` に残り、誰でも見られます。秘密の情報は登録しないでください。

### 2-3. 下書きを保存する

**下書きを保存** を押すと、編集内容が **このブラウザの中だけ** に保存されます（画像も含む）。
次に更新ツールを開いたとき、「下書きを復元する」か「最新の公開データを読み込む」かを選べます。

下書きを保存しても、公開サイトは変わりません。別の端末やブラウザとは共有されません。

### 2-4. 公開用ファイルを書き出す

**公開用ファイルを書き出す** を押すと、入力内容を確認してからファイルをダウンロードします。入力に問題があるときは、直す項目が一覧で表示されます。

- **画像を追加・差し替えていない場合** → `site.json` がダウンロードされます。
- **画像を追加・差し替えた場合** → `pee-portfolio-update-日付-時刻.zip` がダウンロードされます。
  中身は `data/site.json` と、新しい画像（`assets/…`）です。

### 2-5. リポジトリに反映する

#### site.json だけのとき（GitHubの画面でできます）

1. GitHubでリポジトリを開き、`data` フォルダを開く。
2. **Add file → Upload files** を選び、ダウンロードした `site.json` をドラッグ＆ドロップする。
3. **Commit changes** を押す。
4. 数分待ってから公開URLを再読み込みして、変更が反映されたことを確認する。

#### ZIPのとき（GitHub Desktopを使います）

1. ZIPを展開する（右クリック → **すべて展開**）。
2. 展開してできたフォルダの **中身**（`data` フォルダと `assets` フォルダ）を、このリポジトリのフォルダ（`portfolio`）に **コピーして上書き** する。
   同じ名前のファイルを置き換えるか聞かれたら「置き換える」を選びます。
3. GitHub Desktopで変更が表示されたことを確認し、Summaryに「作品を更新」などと書いて **Commit to main** を押す。
4. **Push origin** を押す。
5. 数分待ってから公開URLを再読み込みして、変更が反映されたことを確認する。

> GitHub Pagesへの反映には、Pushしてから数分かかります。リポジトリの **Actions** タブで「pages build and deployment」が緑のチェックになれば完了です。

### 2-6. その他のメモ

- **JSONファイルを読み込む**：書き出した `site.json` などを読み込んで、編集内容をまるごと置き換えます（確認があります）。ファイルに問題があるときは読み込まず、今の編集内容はそのままです。
- **公開データを読み込み直す**：公開中の `data/site.json` を読み込んで、編集内容を置き換えます。
- 作品を削除しても、画像ファイルはリポジトリから削除されません。不要な画像は、必要に応じて手動で削除してください。
- 画像は PNG・JPEG・WebP（1枚5MBまで）に対応しています。長辺が1600pxを超える画像は自動で縮小します。透過は保持されます。SVGには対応していません。
- 下書きの画像データが見つからない（ブラウザのデータを消したなど）ときは、書き出しを止めて、画像の選び直しを案内します。

## 3. 手元のパソコンで確認する（開発用）

`index.html` をダブルクリックで開くと、データを読み込めません。簡単なHTTPサーバーを使ってください。
このフォルダでターミナルを開き、次のコマンドを実行します（Pythonが必要です）。

```bash
python -m http.server 8000
```

- 公開ページ：<http://localhost:8000/>
- 更新ツール：<http://localhost:8000/editor/>

終了するときはターミナルで `Ctrl + C` を押します。

プロジェクトサイト（`/リポジトリ名/` の下）での見え方を確かめたいときは、ひとつ上のフォルダ（`GitHub`）で同じコマンドを実行し、<http://localhost:8000/portfolio/> を開きます。

## 4. データの形式（参考）

通常は更新ツールで編集するので、`data/site.json` を直接編集する必要はありません。

- `schemaVersion`：データ形式のバージョン（現在は `1`）
- `profile`：`siteTitle`（サイト名）、`displayName`（表示名）、`bio`（紹介文）、`image`（プロフィール画像のパス）
- `works[]`：`id`、`name`、`description`、`type`（`web` / `android`）、`url`、`buttonLabel`（空なら「使ってみる」／「配布ページへ」）、`image`、`imageKind`（`icon` / `screenshot`）、`imageAlt`、`visible`
- `links[]`：`id`、`label`、`url`、`icon`（空なら汎用リンクアイコン）、`visible`

リンクのアイコンに使えるキー：`link`、`home`、`x`、`bluesky`、`instagram`、`youtube`、`github`、`nostr`、`misskey`、`pixiv`、`note`

配列の順番が表示順です。IDは更新ツールが自動で付けます。

## 5. 確認済みの項目と、未確認の項目

ローカルのHTTPサーバー（Chromium系ブラウザ）で確認した項目：

- サイト名・紹介文・青うさぎアイコンの表示、9作品（Web 7件／Android 2件）とURL
- リンク0件のときにリンク欄が非表示になること、画像・説明が未登録でも自然に表示されること
- 画像を読み込めないときの代替表示
- 作品・リンクの追加・編集・削除・並べ替え・非表示、キーボードでの並べ替え
- 下書きの保存と復元（画像を含む）、JSONの読み込み（不正なJSON・未対応バージョン・ID重複・型の誤り・危険なURLを拒否し、編集内容が残ること）
- プレビュー（スマホ幅／PC幅）
- `site.json` とZIPの書き出し（ZIPはPythonとWindows標準の展開機能で展開できることを確認）、画像の縮小と透過の保持
- スマホ幅（375px）で横スクロールが出ないこと
- ルートに置いた場合とサブフォルダ（`/portfolio/`）に置いた場合の両方で表示されること、Consoleにエラーがないこと

未確認の項目：

- 実際のGitHub Pagesへの公開と、書き出したファイルを反映したあとの公開ページの更新（リポジトリ作成後に、上の手順で確認してください）
- Safari（iPhone・Mac）とFirefoxでの動作
  - 特にSafariでは、WebP画像を縮小すると自動的にPNGとして保存される場合があります（透過は保持されます）。
